# vERL: A Specification of Expected Run Length for Vessel Segmentation

*Alternative title, if a sharper hook is wanted:*
*Expected Run Length Is Three Undeclared Choices, Not One Number*

## Abstract

*(~130 words)*

Connectivity in vessel segmentation is scored with clDice and Betti numbers.
We construct a case set on which these metrics cannot separate two degradations
that differ eightfold in how much vessel they orphan: Dice is identical to four
decimals, clDice ties, and Betti-0 **ranks the worse prediction better**.
Expected Run Length (ERL), a connectomics metric, separates them. ERL cannot,
however, be adopted as it stands. Running the reference implementation on
retinal data exposes an undocumented connectivity assumption that leaves up to
97.8 % of the covered skeleton unmeasured, and a fragment length that depends
on the order the input nodes are listed. Beyond these defects, ERL conceals
three undeclared conventions whose twelve combinations span 38–42 points on one
set of predictions, against a largest honest effect of 1.4 points. We specify
vERL and give the disclosure a published ERL number requires.

**Index Terms** — retinal vessel segmentation, evaluation metrics, topology,
expected run length, reproducibility

## 1. Introduction

*(572 words including the contribution list)*

Retinal vessel segmentation supports the detection and monitoring of diabetic
retinopathy, glaucoma and hypertensive disease \cite{staal2004drive}. What
makes a segmentation useful downstream is usually not how much vessel area it
recovers, but whether the vessel tree it produces can still be followed.

Four metrics dominate the reporting of that property, and each is limited in a
different way. **Dice** resolves an average of pixel-wise hits and misses
\cite{shit2021cldice}, so severing a capillary removes almost no area and is
scored much like a boundary wobble. **clDice** \cite{shit2021cldice} replaces
the region by its centreline and so restores sensitivity to thin structure, but
it still reports the proportion of centreline recovered rather than whether the
tree remains traversable. **Betti errors**, and **Betti matching**
\cite{stucki2023betti}, which supplies the spatial correspondence that plain
Betti differences lack, return a count of topological features; a count cannot
separate an error that detaches a leaf from one that detaches a subtree.
**cbDice** \cite{shi2024cbdice} adds radius awareness to the centreline, and
remains an overlap proportion. The shortcoming they share is that none of them
returns a length.

**Expected Run Length (ERL)**, introduced for neuron reconstruction in
connectomics \cite{januszewski2018ffn}, does. It asks: starting from a point
drawn uniformly on the ground-truth centreline, how far can the prediction be
traced before it meets an error? Fragments of the centreline that fall inside
one predicted component contribute their length; a point the prediction never
found contributes a run of zero. ERL is not ours and we do not claim it.

Three properties make it the right quantity for this task. It carries a
**unit**: a statement of the form "a vessel can be followed for $N$ pixels on
average" can be checked against the image, which "the Betti-0 error is 19.8"
cannot. It weights an error by the **length that error costs**, so a break at a
tip and a break near the root are not the same event — the distinction §2 is
built on, and the one a count cannot make. And it measures the downstream
quantity **directly** rather than through a proxy for it.

ERL is nevertheless absent from this field. Neither the survey of Berger et al.
\cite{berger2024pitfalls} nor the ShapeMI benchmark of Decroocq et al.
\cite{decroocq2025bench}, whose public implementation covers cbDice, Dice,
Betti matching, Betti error, clDice and ccDice, includes a run-length measure.

The gap does not close by adoption, which is this paper's subject. That an
evaluation convention can reorder methods is not our finding: Berger et al.
\cite{berger2024pitfalls} established it on DRIVE for pixel adjacency, feeding
Betti-family metrics, at mean Spearman $\rho = -0.63$. Our finding is that it
happens on ERL, along three axes they do not touch, one of which changes *sign*
depending on another — and that before any of it applies, the reference
implementation must be repaired.

We therefore propose **vERL**, a specification of Expected Run Length for
vessel segmentation. Our contributions are:

1. A constructed case set on which Dice ties to four decimals, clDice ties
   inside the window a reader would call equivalent, and Betti-0 *ranks the
   worse prediction better*; ERL separates them.
2. The first execution of the reference ERL implementation on retinal data,
   exposing an undocumented connectivity assumption and a fragment length that
   depends on input order.
3. **vERL**: a specification of ERL for vessel segmentation — two requirements
   that are matters of correctness, two recommended conventions, one axis we
   report but cannot settle, and the disclosure list a published number needs.

## 2. A failure the current metrics cannot see

*(545 words; Fig. 1 + Table 1)*

This section establishes two things: that Dice and clDice have no resolution
for a distinction with a clear clinical ordering, and that Betti-0 resolves it
backwards.

### 2.1 Construction

We do not search for model failures; we construct two, and hold everything a
metric could legitimately respond to constant except the one property under
test.

Starting from a ground-truth mask treated as a perfect prediction, we remove
tissue at `\csCuts` locations per arm on each of `\csImages` DRIVE test images
\cite{staal2004drive}. Each excision is a disc of radius twice the local vessel
calibre. The two degraded arms are **paired**: cut for cut, they match on
radius and on deleted area. The arms differ in one respect only — **where along
the branch the tissue is taken**. One arm cuts near vessel tips, the other in
branch interiors. All four degraded arms post the same Dice, `\csDice`
(Table 1).

Which arm is worse is not decided by ERL. Using ERL to argue that ERL is right
would be circular. We anchor quality on an independent quantity: the fraction
of predicted vessel that is **no longer connected to the main tree**
("Unreachable" in Table 1). Interior cuts orphan `\csUnreachMid` % of the tree;
tip cuts orphan `\csUnreachTip` %. Interior cutting is roughly eightfold worse,
and the anchor says so without reference to any run-length quantity.

Two erosion arms act as controls. Eroding the boundary away from the centreline
changes Dice but nothing topological, as expected. Eroding anywhere collapses
ERL to `\csTracedEdgeAny` % while Betti-0 stays at zero and clDice stays above
0.996 — at capillary calibre, eroding the boundary *is* severing, because the
boundary is the centreline. We report this arm because it is the control that
failed, and what it failed at is informative.

### 2.2 What the metrics report

**Dice cannot respond**, by construction: it scores deleted area, and the arms
delete the same area. This is the designed outcome of the pairing, not a
finding.

**clDice cannot separate them.** It scores the proportion of centreline
recovered; the arms are paired on calibre and deleted area, so each removes
comparable centreline mass, and the property they differ in — where that mass
sat in the tree — is not one a proportion of recovered centreline expresses.
They tie at `\csClTip` against `\csClMid`, a fourth-decimal difference no
reader would take as a ranking.

**Betti-0 inverts.** It reports `\csBettiMid` for interior cuts against
`\csBettiTip` for tip cuts; lower is better, so it prefers the arm that orphans
eight times more vessel.

The mechanism behind the inversion is measured, not argued. A cut increases the
component count only
if it disconnects the mask. Cutting a tip detaches the distal stub immediately.
Cutting a branch interior often does not, because the retinal ground truth
contains loops: arteries and veins cross in projection, and a severed edge on a
cycle leaves the mask connected. Of `\csCuts` interior cuts, only
`\csSplitsMid` add a component, and `\csLoopsMid` fall on such loops. Betti-0
is therefore close to blind to the degradation that matters most.

ERL separates the arms by `\csGap` points (`\csTracedTip` % against
`\csTracedMid` %), in the direction the anchor gives.

**Scope.** The case set is *constructed*. It establishes that these metrics have
no resolution for this distinction; it does not establish how often models fail
this way in practice.

## 3. The metric does not transfer off the shelf

*(560 words; Table 2)*

Adopting ERL means adopting an implementation. The reference is the Allen
Institute package `segmentation-skeleton-metrics` \cite{allenskeletonmetrics},
version `\refVersion`, and its formula is not in dispute: our transcription and
its output agree to floating point on cases where the answer can be computed by
hand. What does not transfer is the *walk* that evaluates that formula. It
fails in two independent ways, and both are invisible in the domain the package
was written for.

To avoid testing a port rather than the metric, we did not move DRIVE through
the package's SWC/volume pipeline. We built its `LabeledGraph` directly — one
node per skeleton pixel, 8-adjacency, voxel coordinates $(0, r, c)$ so that its
Euclidean `physical_dist` yields 1 for orthogonal and $\sqrt{2}$ for diagonal
steps, node label the id of the predicted component covering that pixel and
`"0"` where uncovered — and called its own `compute_graph_erl`. On synthetic
straight-line breaks its output is float-equal to our `(split, edges, covered)`
cell, which is the verification the previous paragraph relies on: the
transcription is established before any defect is claimed.

**An undocumented connectivity assumption.** The package's loop takes, for each
label, the nodes carrying that label and walks the run length **from the first
of them**; its walk covers only the connected component containing that node.
Its loader assigns segmentation labels directly and has no step that splits a
label which is disconnected on the ground-truth skeleton. In 3D connectomics
the assumption behind this usually holds: a segmented neuron meets the
ground-truth skeleton in one place. On a retinal image it fails, and it fails
worse the better the prediction is, because a good prediction is a *single
connected* vessel tree whose covered skeleton is broken at every gap. Table 2
gives three images: on image 01, `\refUnwalkedA` % of the covered skeleton is
never walked and the reported ERL is `\refErlA` px against `\refErlAFixed` px
after the labels are split — a factor of roughly 300. The discrepancy is not a
fixed bias that a reader could correct for; across the three images it ranges
from 13.7 % to `\refUnwalkedA` % of the skeleton.

**Fragment length is not well defined.** The walk builds a DFS spanning tree
and keeps every diagonal edge it traverses. Under 8-adjacency a pixel skeleton
is full of short cycles — staircases and L-corners — and a graph with a cycle
has more than one spanning tree. The three-pixel corner $(0,0), (0,1), (1,1)$
is a triangle; over its six node orderings the package returns `\refCornerA` or
`\refCornerB`. In its pipeline that ordering is the order of points in the SWC
file. The same effect explains the residual on real images: after the
connectivity defect is repaired, its values remain 0.76 %–1.71 % above ours
across nine comparisons, from these undeduplicated diagonals.

**One half of the metric is inert here.** The merge penalty — the term that
distinguishes ERL from a split-only measure — never fires on retinal data,
because the ground truth is a single connected object. What transfers is half
the metric.

**Honesty about scope.** Table 2 is transcribed from a run on 2026-09-05; the
package is not installed in this repository's environment and the table is not
recomputed by `exp/paper_figures.py`. The connectivity result depends on our
reconstruction of the package's input; the ordering result does not — it is the
package's own function on a three-node graph.

## 4. vERL: a specification, and what it costs to ignore it

*(702 words; Fig. 2, Fig. 3, Table 3)* — **the section to cut first if the build overruns**

Even once the two defects of §3 are repaired, one number cannot be quoted for
ERL, because the definition leaves three choices open and nobody declares which
they took.

### 4.1 Three undeclared choices

Computing ERL requires three decisions that published numbers do not state.
**Denominator:** the covered skeleton, or the whole ground truth.
**Fragment length:** pixel count, 8-neighbour edge weights, or diameter.
**Splitting rule:** does an uncovered centreline pixel end a run even when the
prediction bridges the gap? Two by three by two is twelve legal cells.

The under-specification is not of our making. The reference package emits both
`ERL` (covered denominator) and a normalised ERL divided by the full skeleton
length, and papers citing "ERL" do not say which they used.

Read under all twelve cells, `\specArms` arms at `\specSeeds` seeds each span
`\specSpreadLo`–`\specSpreadHi` points (Table 3, Fig. 2) — with nothing about
the model, the data, the threshold or the checkpoint changing. For scale, the
largest effect any published topology loss produces in our own experiments,
each arm read at its own dev-optimal threshold, is `\specHonest` points. The
ranking does not survive the choice either: between the two extreme cells,
Spearman $\rho = \specRho$, with a largest rank move of `\specMove` of
`\specArms`.

Two axes interact, which is why they cannot be reported separately. Bridging
exceeds splitting for 10 of 10 arms under pixel and edge lengths, and for 0 of
10 under diameter. Bridging merges two fragments, so mass adds; but a bridge
landing on a T-junction adds a branch rather than extending the longest path,
so the diameter of the merged fragment can fall below the mass-weighted mean of
its parts. Three separate one-axis tables cannot show this.

### 4.2 The specification

The twelve cells are not twelve choices of the same kind. Two are matters of
correctness, two we can settle on evidence, and one we cannot.

**Required, because these are correctness.** (R1) Fragment length must not
depend on the order the input nodes are listed. (R2) A label that is
disconnected on the ground-truth skeleton must be split before measurement.
Neither claim needs cross-dataset support: a rule returning two values for one
shape is not a convention, and dropping `\refUnwalkedA` % of the skeleton
without saying so is not a design choice.

**Recommended, because the evidence is one-sided.** Use edge weights for
length — they satisfy R1, and differ from pixel counts by 0.2 points, so the
choice is nearly free. Use the **full** denominator. This is not a stricter
variant of ERL but its definition: a point drawn on the ground-truth centreline
that the prediction never found contributes a run of length zero and must stay
in the denominator. The covered denominator quietly conditions the question on
what was found, and so rewards a method for finding less.

**Required in reporting: both denominators, as numbers.** Our value equals the
reference value times coverage per image, to floating point — but the identity
does not survive averaging (42.0 × 81.7 % = 34.3 ≠ 34.8; the mean of a ratio is
not the ratio of means). Printing coverage alone therefore does not let a
reader reconstruct the other denominator.

**Left open, because one dataset cannot settle it.** We report **split**: it
cannot be gamed by painting vessels thicker, and it is the simpler rule to
reproduce. We do not claim it is correct. It differs from bridging by 24.3
points under pixel length, and the sign of that axis is set by the length rule,
so deciding it needs evidence across datasets and architectures.

### 4.3 When the disagreement is large

The spread is not a constant. It is bounded by how much ground-truth skeleton
the prediction fails to cover, so it collapses on easy data (Fig. 3): VessMAP
\cite{comin2025vessmap} spans `\txVessMAPLo`–`\txVessMAPHi` points at
`\txVessMAPCov` % coverage, against STARE \cite{hoover2000stare} at
`\txSTARELo`–`\txSTAREHi` points and `\txSTARECov` % coverage, with HRF
\cite{budai2013hrf} between them. Read backwards, this gives a reader a way to
bound the disagreement a published ERL number conceals, from its coverage
alone.

### 4.4 What to report next to a vERL number

1. The denominator, the length rule and the splitting rule.
2. Coverage, and both denominators' values.
3. The amount of predicted foreground — vERL is gameable by painting.
4. Which annotator was taken as ground truth.
5. That the merge term does not fire, and that crossings are unpriced.

## 5. Conclusion

*(147 words)*

Betti-0 ranks a degradation that orphans `\csUnreachMid` % of the vessel tree
above one that orphans `\csUnreachTip` %, and clDice and Dice cannot separate
them at all; a run-length metric can. But ERL does not arrive ready for this
field. Its reference implementation leaves up to `\refUnwalkedA` % of the
covered skeleton unmeasured on a retinal image and returns a length that
depends on input order, and the metric itself hides three conventions whose
twelve combinations span `\specSpreadLo`–`\specSpreadHi` points where the
largest honest effect is `\specHonest`. vERL fixes the two defects, fixes two
of the three conventions, and states what the third costs. Three limits bound
this: the case set is constructed, so it shows an absence of resolution rather
than a frequency of failure; the quality anchor speaks to the cut arms and not
the erosion arms; and the main results are on DRIVE alone.
