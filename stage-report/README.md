## 這一系列真正學到的東西

九件比任何單一數字都重要的事：

**一、單一平均指標會系統性地隱藏方法差異。**
E2 在 DRIVE 上、E4 在 TopoMortar 上、E6 在不確定度上，
三次看到同一個模式：一個總數把兩個方向相反的效應平均掉。
分層報告的成本是零。

第四次出現在 E9b 自己身上，而且是當天早上寫的報告：
HRF 的整體迴路缺口是 −40.7，看起來焊接理所當然該有效。
拆開來是**健康影像 +1.3、病變影像 −56 到 −67**——
健康視網膜的模型根本沒有缺口，焊接在那裡是有害的（4/5 張變差，p = 0.017）。
修正後的說法：**有缺口時焊接有效（三個資料集都複製，−4.7 到 −13.6），迴路數接近正確時有害，過多時中性**。
這條規則是**逐影像**的：TopoMortar 整體方向相反，它自己的 89 個深缺口單位仍然改善 −6.8。

**二、加一個控制變項，經常會翻掉原本的解讀。**
本系列有五次自我推翻：
stage 0 的「clDice 免費獲勝」被連通塊過濾推翻；
E3' 的「用 vk 訓練拓樸較好」被骨架精度推翻；
E6 的「結構層級救回了暗處」被等大對照組推翻；
E4 的「β₁ 上 loss 贏過濾 15 倍」被 E9 的填洞掃描推翻；
E9 的「β₁ 只能從模型端修」被 E9b 的焊接掃描推翻——**同一天內推翻自己**。
每一次都是加一個對照，不是換一個模型。

第四、五次合起來給了一條可操作的規則，而且第五次示範了它多容易套錯：
**每一個拓樸指標的每一個方向都有對應的後處理操作，要先排除，宣稱才站得住。**

| | 太多 | 太少 |
|---|---|---|
| β₀（連通塊） | 移除小連通塊 | 焊接斷口 |
| β₁（迴路） | 填補小洞 | 焊接斷口 |

E4 只掃了左上一格就對兩個指標下結論；
E9 補了左下一格，卻把「移除型不行」推廣成「後處理都不行」；
E9b 補上右邊那一欄，推翻 E9。**規則寫對了，套用時漏掉一半的操作空間。**

**三、模型端的訊號會一起瞎。**
E1' 量到逐像素信心在最暗的一層反向失效（AUROC 0.373）。
E8 換了三種讀出方法——平均、種子分歧、不同標註者訓練的模型之間的分歧——
在 Q2 以上都有效，**在最暗那一層全部仍然反向**。
換讀出方法救不了，只能改模型學到什麼。

**四、統計單位是「訓練」，不是「影像」。**
E5 用 700 個 (影像, 種子) 配對算出 p = 3×10⁻⁴，
而那個差值在僅有的兩顆種子之間符號相反（−0.0271 / +0.0102）。
700 對來自 **2 次訓練**；配對檢定量到的是「同一個模型在不同影像上表現一致」，
不是「這個 loss 比較好」。這叫**偽重複**，而且 √n 會放大它：
同樣的種子間偏移在 n=60 只給 |t| = 0.99，在 n=700 給 |t| = 11.9。
**n 愈大，錯的方法愈自信。**
配對仍然值得做（它移掉影像難度的變異），但不能單獨成立——
現在的規矩是配對檢定「且」每顆種子符號一致，
已寫進 `summarize_gated.py` 的事前判準，在 E7 結果出來前裝上。

**五、「量到的性質」和「介入的效果」是兩回事。**
E1' 量到模型對自己漏掉的暗血管很有信心（AUROC 0.373）。那個量測完全正確，而我把它當成了「別用信心當訓練訊號」的禁令，寫進 E7 的整個假設。
錯在：那是一個描述**收斂後**模型的量測，不能用來預測一個在**每一步**改變優化路徑的介入。
診斷描述的正是那個訊號要去修的病。
附帶的一條：**控制組要當成真的實驗來設計**——`G_focal` 只是為了讓判準 3 有東西可比才存在，現在它是本系列最好的模型端結果。

**六、一個看起來完整的結果檔，不代表它讀到了完整的資料。**
E12 訓練了種子 3–5，`stratify.py` 和 `break_lengths.py` 各自把種子範圍
**手寫成 `(0, 1, 2)`**，於是它們算的是舊的那三顆。
`summarize_confidence.py` 照樣印出一份格式完整的判定，
而那份判定**開啟了下一個實驗的佇列閘**。
沒有任何一步報錯，檔案是新的，內容是錯的。

同樣的手寫種子範圍在 repo 裡有**五份拷貝**
（`stratify` / `break_lengths` / `hole_sweep` / `breaks` / `speckle`），
所以這不是一次筆誤，是一個會被複製的形狀。
修法是 `train.trained_runs()`——去掃磁碟，而不是宣告一個範圍；
檢查寫在 `test_trained_runs.py`，斷言的正是失敗的那條性質：
**一個 seed 9 的目錄要被找到，一個只有 `ckpt.pt` 的半成品不能被算進去。**

推而廣之：**閘門要擋在「數字是對的」上，不是擋在「檔案存在」上。**
CLAUDE.md 早就寫了「絕不等 PID，要等成品」——這次成品有了，成品是錯的。

**七、一個決定只搬一半，比完全不搬更危險。**
E16 把「要不要把輸入編碼成 LIOT」從呼叫端搬進 `predict_full`
（讓它從模型自己讀），而且我在報告裡把這寫成優點。
但「用哪組正規化常數」留在呼叫端沒搬。

於是三支分析程式**正確地編碼，然後用灰階常數正規化 0–255 的位元組**——
輸入落在 800 個標準差之外，模型什麼都不輸出，
判定印出 Dice 0.0000 當成一項關於 LIOT 的發現。
`transfer.py` 沒中，只因為我在那裡另外寫了一份常數邏輯：
**同一個決定在 repo 裡有兩份實作，一份對一份錯。**

如果兩半都留在呼叫端，呼叫端至少會看見它們並列而想起要一起改。
搬走一半之後，剩下的那一半看起來就只是個普通參數。

修法是 `train.normalisation()`（兩件事一起決定，一次），
加上 `predict_full` 的守衛：**4 通道模型收到純量常數就丟例外**。
那一行讓安靜的錯誤變成大聲的錯誤，本來就該存在。

推而廣之：**把決定搬進函式時，要搬走的是「整個決定」，不是它的一半。**
搬完之後問一句：呼叫端還剩什麼參數是必須和我剛搬走的東西一致的？

**八、判準要蓋滿所有可能被犧牲的維度，不是我猜的那一個。**
兩次犯同一類錯：
E14 的判準 1 押在 Q1，因為我預期效果在那裡——結果 Q1 是種子變異最大的一層，判準倒在那裡。
E18 的判準 4 保護 Q4，因為 E15 說那層在天花板、只會賠不會賺——
結果賠在 **Q2（−0.0539）和 Q3（−0.0237）**，兩層都沒有任何判準看著。
Q4 賠 0.0030 被抓到並判 FAIL，Q2 賠的是它的十八倍，完全隱形。

E18 那次結局是好的（ERL 顯示 Q2 的 Dice 損失是良性的，那些像素反而連得更好），
**但那是運氣。** 如果損失是真的，那套判準會印出「三條通過、推薦採用」而看不見它。

分層報告的成本是零（第一條），所以沒有理由只保護一層。
**規矩：分層指標的事前判準要每一層都有一條，非劣性也算。**

**九、先查文獻再設計實驗。**
stage_1 初版規劃的五個實驗有兩個撞到既有工作，
直接開跑會浪費約 22 小時運算並得到沒有貢獻的結果。
但 E0 也補上後半句：**查到撞題不要直接放棄，要讀進實驗設定確認撞的是哪一塊**——
那兩篇在摘要層級看起來重複，在實驗設定層級其實互補。

E7 補上第三句，而且是反方向的：**查到「沒人做過」的時候，要確認自己列舉的維度是完整的。**
E7 把設計空間寫成「權重來自影像端 vs 模型端」兩格，宣告沒人做過影像端。
那句話沒錯，但 2026-08-24 重查時發現 Smooth clDice 佔著**第三格：幾何端**
（權重來自血管邊界周圍的空間不確定帶）。
那個維度真正的名字是「權重從哪個來源推導」，它至少有四個值：
**影像、模型、標籤、幾何**。列兩格就宣告涵蓋，是把「我想到的」當成「存在的」。
