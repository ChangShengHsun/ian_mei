# 讀者已經有 Dice、clDice、Betti-0 了，ERL 還多告訴他什麼？

2026-09-04。`exp/metric_redundancy.py`，CPU，秒級，已跑完。
**這是論文的存在性檢查**，也是四張表裡唯一一張寫來是為了**有可能殺掉論文**的。

## 為什麼一定要做

論文（寫法 a）主張這個領域應該採用 ERL，並規定怎麼報。審稿人的第一個問題
必然是論文還沒回答的那個：**這個領域已經有 Dice、clDice、Betti-0 了。
如果 ERL 排出來的名次跟 clDice 一樣，那你提的是同義詞，論文沒有存在理由。**

所以這支腳本的預先登記裡寫了一個**擊殺條件**：
若 `ρ(ERL, clDice) > 0.95` 且成對不一致率 < 10%，則就排名而言 clDice 是替代品，
論文必須明講，並把立論改到「可解釋性」（有單位、有天花板的長度）而不是排名。
**先寫下來，結論才不能事後偷偷放軟。**

資料是既有的 `checkpoint_scores.csv`：97,400 列，每列一個
(run, epoch, image)，dice / cldice / betti0_err / erl **同時**在同一列，
所以不用重新計分，四個指標之間也不可能走鐘。
epoch 用 `chosen_epochs()`（讀各 run 自己的 `log.csv`，不碰測試圖）。

## 結果一：四個指標排出來的名次不一樣

**兩組臂，因為它們回答不同問題，而第二組有一部分是「設計出來的」。**

| 指標 | 全部 56 臂 ρ | 不一致對 | 10 個 ledger 臂 ρ | 不一致對 |
|---|---|---|---|---|
| Dice | **−0.304** | 60.2% | **−0.830** | 84.4% |
| clDice | +0.307 | **36.6%** | −0.370 | 60.0% |
| Betti-0 誤差 | +0.177 | 42.5% | −0.345 | 62.2% |

**56 臂是未經挑選的集合（含所有退役配置），10 個 ledger 臂是論文用的那組，
而後者刻意掃了一條 Dice 換 ERL 的取捨（`clw` 權重 1–64，已定案第 3 條）——
所以那裡出現負相關是那條取捨的示範，不是獨立發現。**
論文引用 56 臂那個數字當發現，10 臂那個當機制。

即使如此，56 臂上：**clDice 把 36.6% 的臂對排反了。** clDice 是這個領域的
連通性指標，它不是 ERL 的替代品。**擊殺條件沒有觸發。**

## 結果二：這是給讀者看的那一句

| 對齊的指標 | 最寬視窗 | 該視窗的 ERL 範圍 | 所有視窗中位數 |
|---|---|---|---|
| Dice ±0.002 | 9 個 run @ 0.7730 | 11.9% → 63.2%，**差 51.3 點** | 20.0 點 |
| clDice ±0.002 | 22 個 run @ 0.8153 | 21.3% → 73.0%，**差 51.6 點** | 33.3 點 |

**兩個模型在 clDice 上一模一樣（差在 0.002 以內），可追蹤長度可以差 50 個
百分點。** 對齊 Dice 是同樣的故事。

「視窗」的定義是：以某個 run 的值為中心、容差以內的所有 run——也就是一個
只看該指標的讀者會判定為等價的那群模型。

## 結果三：ERL 有單位，其他三個沒有

```
最差的 run  A_dice_dir_snake_k16_t2_s0    1052 px
最好的 run  K_focal_aug_clw64_s2          6423 px
```

「在撞到錯誤之前可以追蹤 1052 像素」是一句話。
Dice、clDice、Betti 數都講不出這種句子。這是相關係數證明不了、但對採用與否
最有分量的論點。

## 誠實的但書

1. 10 臂那組的負相關**部分是建構出來的**（`clw` 掃的就是這條取捨）。報告裡
   已經把這句話印在表的正上方，不是藏在註腳。
2. ρ 是**臂層級**的（每臂先對種子與 20 張圖平均）。逐張圖的相關會被影像難度
   主導，那不是「指標排不排得一樣」這個問題。
3. 這裡的主表 ERL 全部是 `split` / `pixels` / `full` 那一格，且閾值是
   `sweep_score.py` 的固定值。~~三個約定對這張表的影響沒有量，列為未決。~~
   **2026-09-04 同日補測，已關閉（報告的 1b 節）**：`composition` 的 `raw`
   列同時帶 `erl_split`、`erl_bridged` 與 `dice`，在**同一個閾值同一張圖**，
   所以切分軸（值 20 點的那一個）可以精確回答且不用新計算。結果是
   **約定不翻轉這個結論**：

   | ERL 約定 | ρ vs Dice | 不一致對 |
   |---|---|---|
   | `erl_split` | −0.867 | 84.4% |
   | `erl_bridged` | −0.842 | 82.2% |

   兩個約定**彼此**的 ρ 是 **0.964**，對 Dice 的正負號在兩者下相同。
   意思是：約定會大幅改變 ERL 的**數值**（`erl_spec` 量到 38–42 點），
   但**不改變它與 Dice 的排序關係**。這對論文是乾淨的好消息——
   「該不該採用 ERL」這個結論不依賴你選了哪個約定。
   限制：`composition` 沒有 clDice 與 Betti-0 欄，所以這一節只對 Dice；
   長度軸與分母軸仍未測（需要在 `erl_spec` 的操作點重算 dice/cldice/betti）。
