# E16 · 不要教模型看穿低對比，直接把對比刪掉

2026-08-23 排入佇列。三次訓練（`J_liot` × seed 0–2），約 2.5 小時。

**本報告第 0 到第 5 節寫在任何一次訓練啟動之前，一個結果都沒有。**
判準同時寫進 `exp/summarize_liot.py`，該檔先跑過 `--selftest` 才排隊。

## 0. 為什麼是這一個

把整個系列的量測擺在一起，指向同一個地方：

| 來源 | 量到的 |
|---|---|
| [[e2_contrast_stratified]] | 決定一條血管抓不抓得到的是**局部對比**，不是粗細 |
| [[e3_e1_annotator_topology]]（E1'）| 模型對自己漏掉的暗血管**很有信心**（AUROC 0.373，反向）|
| [[e8_ensemble_uncertainty]] | 四種不確定度讀出方法，**全部在最暗那一層失效** |
| [[e15_expected_run_length]] | Q3/Q4 已在天花板的 98–99%，**Q1 只有 17–24%** |

到目前為止的每一個介入——加權 clDice、對比閘、信心閘、資料增強——
都是在**教模型更在意暗血管**。E8 的結論是這條路在最暗那層走不通。

LIOT 換一個方向：**在模型看到之前，就把「暗」這件事刪掉。**

## 1. LIOT 是什麼

[Shi et al., TIP 2021](https://arxiv.org/abs/2202.12587)。
四個方向、每個方向八個距離，比較中心像素與該處的鄰居，中心比較亮就記一個位元，
八個位元打包成一個位元組，一個方向一個通道：

```
channel_d(p) = Σ_i  2^(i-1) · [ I(p) > I(p + i·d) ]
```

結果只取決於四條射線上像素的**大小順序**，
所以對影像套任何嚴格遞增的映射，輸出完全不變。
**5% 對比的血管和 50% 對比的同一條血管，產生一模一樣的 LIOT 編碼。**

`exp/liot.py` 把這件事寫成斷言而不是說明：
gain、bias、gamma 2.2、開根號——四種映射之後編碼逐位元相同；
而把影像反相（改變順序）就會變。

[[e0_literature_check]] 當初查到 LIOT **一個拓樸指標都沒報過**，
所以這裡有一塊真空。

## 2. 為什麼對手是 H_aug 而不是基線

[[e14_augmentation]] 之後，`A_dice` 不再是有意義的對照。
贏一個沒有資料增強的管線只能證明資料增強有用，那已經知道了。

所以兩個 arm 是 `H_aug` 與 `J_liot`，它們共用：
同一個 loss（BCE + soft Dice）、**同一組增強**、同樣的寬度、同樣的種子。
差別只有一件事：網路看到的是灰階，還是 LIOT 的四個通道。

`summarize_liot.py --selftest` 把「只差一件事」寫成斷言，
包括 `AUGMENTS[J_liot] == AUGMENTS[H_aug]`。

**保留 jitter 是刻意的。** LIOT 對遞增映射不變，所以 gamma/gain/bias 擾動
在這個 arm 裡幾乎是個空操作——但「幾乎」是要量的，不是假設的
（jitter 會夾到 [0,1]，夾住會製造相等的像素，而相等會翻掉嚴格大於的比較）。
`test_liot_pipeline.py` 量了：合成影像上 **0.0000%** 的位元改變。
拿掉 jitter 會讓兩個 arm 差兩件事，那就白跑了。

## 3. 三個沒有 loss 會抱怨的坑

輸入從 1 通道變成 4 通道，動到 `build_model`、`sample_batch`、`predict_full`
與正規化常數。這一類錯誤全都不會報錯，只會安靜地訓練出比較差的模型。

**一、裁切邊界。** LIOT 在一個像素上會讀到 8 px 外。
直接在 48 px 的貼片上算，每個貼片都會有一圈射線被裁切邊緣夾住的像素——
一個**只存在於訓練、不存在於整張推論**的假影。
做法：裁 48 + 2×8 = 64 px，編碼，再裁回 48。
檢查斷言的是「加寬會改變貼片邊界、不會改變貼片中心」。

**二、每通道各自正規化。** 四個方向在視網膜上的分佈不同（血管主要從視盤放射出去），
所以是 4 個 mean/std，不是一個；而且只在 FOV 內統計。

**三、對齊。** 幾何變換必須同時作用在影像、標籤、距離圖上。
檢查用「影像就是標籤本身」的合成資料，而且**結構是亮的**：
背景像素不可能比任何鄰居更亮，所以四個通道都必須恰好是 0。
影像和標籤只要有一步沒同步，就會有標籤說是背景的位置落在影像的結構上，編碼非零。
（這條斷言我第一次寫反了，因為順手套用了「血管是暗的」——
合成資料裡結構是亮的。斷言失敗，是斷言錯不是程式錯。）

`predict_full` 從**模型**讀取要不要編碼，不是從呼叫端拿參數，
因為每一支分析程式都只拿著一個檢查點和一張影像來呼叫它。
餵錯的話 4 通道的第一層卷積會拋例外——這正是把決定放在這裡的理由。

## 4. 事前判準（在任何一次訓練啟動之前固定）

寫在 `exp/summarize_liot.py`。種子閘（[[e5_label_noise]]）與真切斷計數
（[[e10_break_anatomy]]）內建，不可選。

| | 判準 | 通過條件 |
|---|---|---|
| **1** | `J_liot` 在最暗一層的 Dice 贏 `H_aug` | 差值 > 0、t > 2、三顆種子全正 |
| **2** | `J_liot` 減少最暗一層的**真切斷**數 | 差值 < 0、t < −2、三顆種子全負 |
| **3** | `J_liot` 沒有賠掉最亮一層 | 非劣性 |
| **4** | `J_liot` 贏沒有增強的基線 | 差值 > 0、t > 2、三顆種子全正 |

**判準 3 是預期會有風險的那一條**，而且理由是機制性的：
LIOT 丟掉絕對亮度，而最亮那一層正是絕對亮度最有資訊的地方。
E15 又說那一層已經在天花板的 98%，所以那裡沒有東西可贏、只有東西可賠。

### 四種結果的預先解讀

| 結果 | 意思 |
|---|---|
| 1、2 都過 | **在輸入端刪掉對比，勝過教模型看穿對比。** E8 那條死路有解 |
| 1 過、2 不過 | 又是覆蓋率不是連通性，跟 E7、E12 同形狀。照那樣報 |
| 2 過、1 不過 | 本系列沒出現過的形狀。先用 ERL 對一次再相信 |
| 都不過但 4 過 | LIOT 贏「沒有增強」但輸給「有增強」——它教的東西被 H_aug 涵蓋了 |
| 都不過 | **先別對 LIOT 下結論**，見第 5 節：這裡測的不是它的主場 |

## 5. 一個必須先講清楚的限制：這不是 LIOT 的主場

LIOT 論文的主張是**跨資料集泛化**——在一個資料集上訓練、到另一個上測試，
對比不變性在那裡才會付現。這裡是 DRIVE 訓練、DRIVE 測試，
兩邊的成像條件相同，所以**對比不變性能買到的東西本來就比較少**。

因此判準都不過，只能說「在單一資料集內 LIOT 沒有比灰階好」，
**不能說 LIOT 沒用**。真正對得上論文的實驗是拿這些檢查點去測 STARE 與 HRF，
`exp/cross_dataset.py` 已經有那條路徑。

沒有現在一起跑，是因為它需要一處改動（跨資料集的正規化常數要用該資料集自己的
`liot_stats`，不能沿用 DRIVE 的），而按最短差異優先的原則，
先確認單資料集這一步的管線是對的。**跨資料集是 E16b。**

### 5b. 我們的灰階基線已經做過對比等化了

寫判準之後才注意到的一件事，補在這裡而不是事後：
本 repo 每一個資料集載入器都跑 **CLAHE**（限制對比的自適應直方圖等化，
`clipLimit=2.0`, `tileGridSize=(8,8)`），DRIVE、STARE、HRF、TopoMortar 都一樣。

CLAHE 本身就是一個對比等化步驟。**所以 `H_aug` 不是「原始灰階」，
它是「已經局部等化過的灰階」**，而 LIOT 要賣的正是對比不變性。

後果：**LIOT 在這裡的邊際增益，預期會比論文小**，因為對手已經先拿走了一部分。
這不是設計錯誤（拿掉 CLAHE 會讓所有既有實驗不可比），
但它意味著判準 1 若以小差距不成立，**「LIOT 沒用」與「CLAHE 已經做完了」
在這個實驗裡分不開**。要分開需要第三個 arm（無 CLAHE 的灰階），那是 E16c。

先寫下來，是為了不要在看到結果之後才想起這條解釋。

第二個限制：三顆種子。[[e14_augmentation]] 的判準 1 就是倒在 Q1 的種子變異上
（全距 0.056，Q2 只有 0.003），而這裡的判準 1、2、4 全都押在 Q1。
**如果判準 1 以接近的差距不成立，正確的反應是加種子，不是下結論。**
