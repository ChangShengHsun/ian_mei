## Q1 · 這個領域下一步想做什麼

先講定位。這不是一個空白領域，而是一個**成熟、但卡在一個明確瓶頸上**的領域。
瓶頸從 2019 年之後就沒變過：血管只有 1 到 3 像素寬，Dice 感覺不到它斷掉，
所以整條研究線都在想辦法讓模型不要把血管切成兩段。

依「目前有多少人在做」與「還剩多少空間」，六條線的現況如下。

### 1. 把拓樸約束做便宜（最擁擠）

代數拓樸路線（persistent homology、Betti Matching）數學上最嚴謹，
但是全域、序列式的演算法，難以平行化，3D 上要自寫 C++ 才勉強可用。
所以近三年的主線就是加速：Topograph（ICLR 2025）改用連通元件圖找關鍵區域，
宣稱比 PH 快 5 倍；Skeleton Recall Loss（2024）只對真值骨架化，可離線在 CPU 預算，
省約 90% 計算，代價是變成單向的。TopoSegNet 走「critical points」路線做可擴展的拓樸保持
[verified via search]。

**判斷：這條線已進入微幅改良期。** 2023 年後幾乎每篇新論文的自我定位都是
「修正 clDice 或 Betti Matching 的弱點 W」。想靠再發明一個 loss 進頂會，門檻已經很高。

### 2. 把「寬度」折進拓樸約束（明確的空缺）

所有 persistent homology 系的 loss 完全不管寬度。一條血管畫得太細但連通關係正確，
它們給滿分。對做微血管或神經纖維的人來說這是實質問題，因為管徑本身就是臨床指標
（例如角膜神經纖維密度是糖尿病神經病變的生物標記）。

cbDice 用局部半徑加權去補，但半徑估計本身有誤差。2026-01 有一篇預印本首次把寬度
折進拓樸約束（arXiv:2601.11409），代價是引入 PDE 求解器，且未經審查。
**「便宜 + 管徑感知 + 有形式化保證」目前沒有被接受的解。**

### 3. 對抗標註噪聲（正在升溫，也是 stage 0 最直接命中的一條）

所有拓樸 loss 都預設真值骨架是對的。但 1 像素寬的結構在不同標註者之間根本不一致，
等於在成像解析度極限附近對噪聲做優化。

這條線 2026 年明顯活躍起來：CurvSegFlow（arXiv:2606.21608）用時間條件流匹配處理
噪聲與不完美標註 [verified via search]；YoloCurvSeg 只用一條有噪聲的骨架標註就達到
全監督 97% 效能；SGL 承認標註本身有噪聲，用學習小組集成避免過擬合。
Smooth clDice 的「不確定區」是唯一針對拓樸 loss 的嘗試，但只是技術報告。

**stage 0 的 2.6 與 2.7 節為這條線提供了量化證據**：兩位專家的 Dice 只有 0.7401，
84.3% 的分歧集中在對比最低的兩欄，而換標註者造成的分數變化是換 loss 的 22 倍。

### 4. 圖表示（技術上最有前途，競爭也最激烈）

不要輸出「每個像素是不是血管」，直接輸出圖：節點是分岔點與端點，邊是血管段。
連通性由輸出格式本身保證，而不是像素預測的副產品。
Relationformer（ECCV 2022）、GraphMorph（NeurIPS 2024）是代表。
障礙是需要圖形式的真值，而大部分資料集只有像素遮罩。

### 5. 領域專用基礎模型（新的主戰場）

通用基礎模型在細長結構上是死路（見 Q2），但領域專用的不是。
vesselFM（CVPR 2025）用真實加合成資料訓練 3D 血管專用模型，零樣本泛化，
目前是最強的通用起點，只是評估範圍還窄（4 種模態）。
另有跨模態通用視網膜血管分割的嘗試（arXiv:2502.06987）[verified via search]。

### 6. 量測標準化（最被忽略、也最容易切入）

見 Q3。這條線的論文正在變多，而且拿得到好 venue。

### 小結：如果要押注

文獻本身推薦的第一個專案是把視覺領域的細節保全工具系統性搬過來
（BlurPool、PointRend、FeatUp），做完整消融。
**但 stage 0 的 2.4 節已經對這條線投下一票反對票**：這一族裡最便宜的 BlurPool
在我們的規模上沒有付錢，它拿像素精度換了一點拓樸，而且交易不划算。
這不推翻整條線，但它改變了先驗。

我認為現在最值得押的是第 3 與第 6 條的交集：
**在標註本身不可靠的前提下，重新定義「什麼叫做進步」。**

## Q2 · 為什麼不直接拿大模型或大型影像辨識模型來跑

四個理由，強度由強到弱。

### 1. 通用大模型在細長結構上是架構性失敗，微調救不回來

這是有直接證據的結論，不是猜測。WACV 2026 有一篇診斷性論文證明
SAM / SAM2 / MedSAM 家族在細長分支結構上明確地差，失敗率與物體的「樹狀程度」
及「低對比程度」強相關，而且針對性微調無法解決 [verified: arXiv:2412.04243]。

**機制很具體**：ViT 把影像切成 14×14 或 16×16 像素的 patch 再 tokenize。
一條 2 像素寬的血管在一個 16×16 的 patch 裡只佔約 1% 的面積，
資訊在 tokenize 的當下就被平均掉了。arXiv:2502.03738 實證了「patch 越小效能越好」，
也就是 patch 化本身就是有損壓縮。

這種失敗有一個特別危險的性質：**它不會表現為低信心**。
模型不是「不確定」，而是根本沒有那個資訊的表示。輸出看起來很篤定，只是錯的。

### 2. 我們的瓶頸不是模型容量

stage 0 的數字直接說明這點。一個 11.7 萬參數的模型就達到 Dice 0.811，
已經接近公認的 0.82 到 0.84 天花板。更關鍵的是 2.6 節：
在高對比區，模型偵測率 99.7%，人類一致率 99.4%，兩者幾乎相同。

也就是說，**看得見的部分已經被解決了**。剩下的 21.2% 漏檢有 71.3% 落在
對比最低的四分之一，而那裡連兩位專家都只有 77% 一致。
再多的參數也生不出相機沒拍到的資訊。

在資訊確實存在的地方，小模型已經接近人類；在資訊不存在的地方，大模型也沒轍。
那大模型要贏在哪裡？這個問題目前沒有好答案。

### 3. 下採樣是所有大架構的共同敵人

U-Net 這類架構為了看得更廣，會把影像逐步縮小。一條 1 像素寬的血管在第一次縮小後
就有相當機率消失，之後解碼器再怎麼放大也救不回來。
模型越大通常下採樣層數越多，這個問題只會更嚴重，不會更輕。

### 4. 資料量與實驗經濟學

DRIVE 只有 20 張訓練影像。Transformer 系模型普遍需要大量資料，
SwinUNet 這類純 transformer 在醫學分割 benchmark 上表現不佳，
而 nnU-Net（CNN）框架至今仍是 SOTA 配方 [verified via search]。

還有一個常被忽略的理由：**便宜讓你買得起統計顯著性**。
stage 0 全部 20 次訓練跑在一台筆電 CPU 上，20 小時。
正因為便宜，我才能跑 3 顆種子、跑 4 種 loss、跑 2 位標註者 × 2 折 × 2 種子。
最大的那個發現（22 倍）需要 8 次訓練才成立。
如果每次訓練要 3 天 GPU，這個實驗根本不會被做。

### 誠實的反面

不能說「大模型一律沒用」。三個反例：

- 在極低資料量下（僅 5 張標註），SAM 系方法比 nnU-Net 高約 6.3 個 Dice 點
  [verified via search]。所以「資料極少」是大模型仍有優勢的區間。
- 領域專用基礎模型（vesselFM）是有效的繞路，只是評估範圍還窄。
- Adapter 微調（VesselSAM、UCS）確實有效果，只是它在補救一個根本不適合的表示。

正確的說法是：**通用視覺大模型的 patch 化表示與次-patch 寬度的結構不相容，
這是架構層次的限制；領域專用模型是真的路線，但還年輕。**

## Q3 · 大家是不是都在找更好的方法打 benchmark

大致上是，而且這件事已經被領域內部點名為問題。

### 現況：是的，而且比較方式不可信

同一個資料集名稱底下，不同論文用不同切分、不同 FOV 處理、不同指標實作，
數字互相不可比。有一篇論文專門在盤點 100 篇以上 DRIVE / STARE / CHASE_DB1 論文的
方法學不一致 [verified via search]。STARE 根本沒有官方切分，每篇自己做交叉驗證，
所以 STARE 的跨論文比較基本上是虛構的。

拓樸類指標（Betti 家族、ccDice、Skeleton Recall）每一個都不到 3 歲，
沒有一個成為必填欄位，所以 2024 年用 Betti matching error 的論文，
找不到更早的 baseline 可以比同一個數字。

### 但反抗正在形成，而且拿得到好 venue

這是重點。點名這件事的論文越來越多，而且發表位置不差：

| 論文 | 主張 |
|---|---|
| nnU-Net Revisited（MICCAI 2024） | 直接呼籲 3D 醫學分割要做嚴謹驗證，並顯示 CNN baseline 仍勝過宣稱的 SOTA [verified via search] |
| nnWNet（2025） | 重新檢視 transformer 在生醫分割的角色，呼籲統一評估 benchmark [verified via search] |
| U-Bench | 用 100 個 U-Net 變體做系統性 benchmark [verified via search] |
| TopoMortar（BMVC 2025 oral） | 用受控合成資料證明：資料增強與自蒸餾能讓標準 loss 追上 clDice |
| Metrics Reloaded（DKFZ） | 不是指標，是「哪個任務該用哪個指標」的標準化倡議 |

TopoMortar 的發現特別值得記住：**很多拓樸 loss 的增益可能被高估**，
因為在受控條件下，普通的資料增強就能達到同樣效果。

### stage 0 是這件事的一個獨立案例

我們的 2.3 節基本上重現了 TopoMortar 的教訓，只是換了一個更便宜的對照組。
clDice 在 DRIVE 上宣稱的 22% 拓樸改善，在加入一行 `remove_small_objects` 之後
只剩 6.7%，逐張比較從 20 比 0 掉到 10 比 10。

那一行後處理沒有出現在任何一篇我們讀過的論文的對照表裡。
這不是因為大家不知道它存在，而是因為**沒有人被要求跟它比**。

### 結論

是的，這個領域主要在打 benchmark，而 benchmark 本身有結構性問題。
這既是障礙也是機會。障礙是你很難靠數字說服人；
機會是「用統一 protocol 重跑 N 個方法、報完整指標」這種論文在這個領域有實質貢獻，
而且 TopoMortar 已經證明它拿得到好 venue。

## Q4 · 我們可以做哪些事情來提升成功率

先界定條件：一台筆電 CPU、沒有 GPU 叢集、沒有標註預算、beginner 程度的工程能力。
在這個條件下跟有 GPU 叢集的團隊比 SOTA 分數是必輸的，而且那場比賽本身價值可疑。

### 策略：不要比分數，比量測與診斷

stage 0 已經在 20 小時的筆電運算內產出三個文獻裡沒有的東西：
連通塊的雜點拆解、對比與粗細的混淆變項分離、標註者效應的量化。
這三個都不需要 GPU，因為它們是**在既有模型上重新量測**，不是訓練更大的模型。

這條路的優勢很實際：算力不是瓶頸，想清楚才是瓶頸。

### 六個具體做法

**1. 每個宣稱都附一個便宜對照組。**
從今以後，任何拓樸方法都要跟「baseline + `remove_small_objects`」比，
而不是跟裸 baseline 比。這一個習慣就能篩掉一大批看起來有效、實際上只是在去雜訊的方法。

**2. 報分層指標，不要報單一數字。**
把結果依局部對比切成四層分別報。stage 0 顯示所有方法的差異幾乎都發生在
「連專家都不同意」的那一層，而在證據充足的那一層大家都是 99%。
單一數字會把這兩件事混成一個平均值。

**3. 把標註來源當成一級實驗變因。**
既然它的影響是 loss 選擇的 22 倍，論文的實驗表就該有這一欄。
優先選有多標註者的資料集：STARE（2 位，已下載）、CHASE_DB1（2 位）、
CORN（標註不一致本身就是活躍議題）。

**4. 用受控合成資料隔離混淆。**
TopoMortar 的做法可以直接抄：刻意調控局部對比、刻意注入標註擾動，
看哪些方法的增益會消失。這是唯一能證明「這個增益是真的拓樸改善」的手段。

**5. 選對投稿場域。**
分析型與再現性型論文在 MICCAI、MIDL、Medical Image Analysis 比在 CVPR 有機會。
CVPR 那邊會嫌「沒有新方法」。TopoMortar 進 BMVC oral 是可參考的前例。

**6. 診斷要配一個最小的方法改動。**
純分析論文最大的風險是被嫌貢獻不足。緩解方式是：診斷做完之後，
提出一個由該診斷直接推導出來的最小改動，並證明它只在診斷預測的地方有效。
例如若「低對比處標註不可靠」成立，那對應的改動就是在該區降低 loss 權重
或改用軟標籤，而且它應該只在低對比層帶來改善。

### 一個要避免的陷阱

不要因為「我們找到了一個負面結果」就停在那裡。
負面結果本身有價值，但要成為論文需要三件事：機制解釋、受控驗證、以及一個可操作的建議。
stage 0 的三個發現目前只有第一項比較完整。

## 接下來要跑的實驗

依成本由低到高排列。前兩項不需要重新訓練，可以立刻做。

### E1 · 模型的不確定性有沒有對上人類的分歧

**問題**：模型輸出的機率值（不是二值化之後的結果）在標註者分歧的地方是否也比較接近 0.5？
如果是，代表模型其實「知道」哪裡有歧義，那不確定性輸出就是一個現成的、
沒有被使用的訊號。

**做法**：在 STARE 上用既有模型做推論，取 sigmoid 機率圖，
計算「機率接近 0.5 的程度」與「ah 和 vk 是否不一致」之間的相關性，並依對比分層。

**驗收**：報出分層的相關係數；若在 Q1 層相關性顯著高於 Q4 層，則假設成立。
若不成立，同樣是有用的結論（模型的信心與人類的猶豫無關）。

**成本**：約 1 小時，不需訓練。

### E2 · 對比分層的評估協定

**問題**：如果把 stage 0 全部 20 次訓練的結果依對比分層重報，
四種 loss 的排序會不會改變？在證據充足層它們是不是全部一樣？

**做法**：對既有的 12 個 DRIVE 模型，把 Dice、clDice、β₀ 都依對比四分位分別計算。

**驗收**：產出一張 4 loss × 4 對比層的完整指標表。
明確回答「這些方法的差異是否全部發生在低對比層」。

**成本**：約 1 小時，不需訓練。

### E3 · 用共識標註訓練

**問題**：既然兩位標註者差 43% 的血管量，那用什麼當訓練目標最好？
四個候選：只用 ah、只用 vk、兩者聯集、兩者交集，以及軟標籤
（兩人都標記為 1.0，只有一人標記為 0.5）。

**做法**：STARE，2 折 × 2 種子 × 5 種目標。每個模型對兩位標註者各評分。
關鍵比較是「軟標籤模型對兩位的平均分數」是否高於任何單一標註者模型。

**驗收**：若軟標籤在兩位標註者上的最小分數高於單標註者模型的最小分數，
則「承認歧義」優於「挑一個人跟」，這是一個可寫的結論。

**成本**：20 次訓練，約 21 小時 CPU。可過夜跑。

### E4 · 過濾發現的跨資料集驗證

**問題**：`remove_small_objects` 贏過 clDice loss 這件事，只在 DRIVE 成立，
還是普遍現象？

**做法**：把 CHASE_DB1（28 張，2 位標註者）與 HRF（45 張，高解析）加入，
重跑 baseline 與 clDice 兩組，並掃描過濾門檻。
注意 HRF 解析度高很多，門檻需要依血管寬度縮放而不是用固定像素值。

**驗收**：報出三個資料集上「過濾帶來的改善」與「clDice 帶來的改善」的比值。
若三者一致，這個結論就可以寫成通則。

**風險**：CHASE_DB1 的官方頁前次連線被 403 擋掉，需要另尋鏡像。
若拿不到就只做 HRF。

**成本**：約 1 天。

### E5 · 受控標註噪聲實驗

**問題**：拓樸 loss 是否比 Dice 更容易被標註噪聲帶壞？
這是 P2 的正面檢驗。

**做法**：在 DRIVE 真值上人工注入擾動，擾動強度依局部對比調整
（模擬「暗處的標註比較不可靠」這個已量測到的現象），
然後比較四種 loss 在乾淨測試集上的退化速度。

**驗收**：畫出「注入噪聲強度」對「測試分數」的曲線，四種 loss 各一條。
若拓樸 loss 的曲線下降得比 Dice 快，P2 就有了直接證據。

**成本**：約 1 天。

### 順序與理由

先做 E1 與 E2，因為它們免費、當天就有結果，而且會影響 E3 到 E5 的設計。
E3 是目前最有可能直接產出可發表結論的一項，優先於 E4 與 E5。
E4 決定 stage 0 的結論能不能寫成通則，重要但不緊急。
E5 智識價值最高，但實驗設計最容易出錯（怎麼注入噪聲才算公平是個真問題），
應該等 E1 到 E3 累積的實作經驗之後再動手。
