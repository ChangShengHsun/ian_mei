# E12 · 信心閘的確認實驗

2026-08-21 啟動。六次訓練（`B_cldice` 與 `G_focal` 的 seed 3、4、5），約 7 小時。

**本報告的第 0 到第 3 節寫在六次訓練啟動之前，結果一個都還沒有。**
判準同時寫進 `exp/summarize_confidence.py`，那份程式先跑過 `--selftest` 才排隊。

---

## 0. 為什麼需要這個實驗

[[e7_contrast_gated]] 的事前判準三條中兩條不成立。
主張「加權訊號必須來自影像，不能來自模型信心」被推翻，
而且是往反方向推翻的：**控制組 `G_focal`（模型端信心閘）贏了假設組 0.0177 Dice。**

`G_focal` 同時也贏了 clDice 基線：Q1 上 +0.0136，三顆種子同號。
拓樸敏感度 +0.0377、精確度只掉 0.0026，所以不是靠多預測買來的。

**但那是事後發現。** 判準不是為它寫的，它是看了結果才被拿來當主角。
三顆種子的離散又很大：+0.0043 / +0.0070 / **+0.0297**，一顆是另一顆的七倍。

這個形狀在本系列出現過兩次，結局相反：
E2 的 +0.0213（+0.0307 / +0.0243 / +0.0088）撐住了；
E5 的 p = 3×10⁻⁴ 在兩顆種子之間符號翻轉，垮了。
**用現有資料沒有辦法分辨 G_focal 是哪一種。**

---

## 1. 這個閘實際上在做什麼

`G_focal` 與 `F_gated` 只差一件事：加權 clDice 的權重從哪裡來。

```python
def confidence_weight(prob, gamma=GATE_GAMMA):
    return 1.0 + gamma * (1.0 - 2 * (prob.detach() - 0.5).abs())
```

`1 − 2|p − 0.5|` 是**猶豫度**：p = 0.5 時是 1，p = 0 或 1 時是 0。
所以模型愈不確定的地方，clDice 項的權重愈高（γ = 1.0 時最高 2 倍）。
`.detach()` 讓權重不參與反向傳播——它是一個調節器，不是可學的參數。

權重進到 `weighted_cl_dice` 的**全部四個和**（精確度與敏感度的分子分母都算），
這一點在 `exp/test_gated.py` 裡有斷言：
加權是把壓力**重新分配**，不是整體加壓。

γ = 1.0 從來沒有調過。這次也不調——先確認效應存在，再談調它。

## 2. 事前判準（在六次訓練啟動之前固定）

寫在 `exp/summarize_confidence.py`。每一條都要同時通過**合併配對檢定**
與**六顆種子符號一致**——後者是 [[e5_label_noise]] 逼出來的那道閘。

| | 判準 | 通過條件 |
|---|---|---|
| **1** | `G_focal` 在最暗一層的 Dice 贏 `B_cldice`（過濾後） | 差值 > 0 且 t > 2 且六顆種子全正 |
| **2** | `G_focal` 沒有賠掉最亮一層 | 非劣性：不是「差值 < 0 且 t < −2 且六顆全負」 |
| **3** | `G_focal` 在最暗一層的**真切斷**數比 `B_cldice` 少 | 差值 < 0 且 t < −2 且六顆種子全負 |

**判準 3 是 E7 供不出來的那一條。**
[[e10_break_anatomy]] 量到斷口數有 93% 在量中心線覆蓋率、只有 7% 真的切斷連通性，
所以要對拓樸下結論，必須用 `severs` 計數。
`break_lengths.py` 現在會為每一個 run 產生它。

三條全過 → 信心閘改善暗處、不賠亮處，而且增益是拓樸的。
1 與 2 過、3 不過 → 增益是**中心線召回率**，不是連通性；就照那樣報。
1 不過 → E7 的結果是事後的，而且沒有撐過新種子。

---

## 3. 兩件必須先講清楚的限制

**一、六顆種子仍然很少。** 這道閘擋得住符號翻轉，擋不住
「效果真實但幅度不確定」。E2 撐住了判準，效果量仍然在 +0.0088 到 +0.0307 之間浮動。
就算三條全過，能宣稱的是**方向**，不是幅度。

**二、`B_cldice` 的 s3–s5 也要重新訓練**，不能只訓練 `G_focal` 然後對上舊的 s0–s2。
配對必須同種子同影像，否則比較的是兩組不同的初始化。
所以是六次訓練，不是三次。

---

## 4. 結果

六次訓練於 08-23 01:56 跑完。判準沒有動過。

```
=== E12 pre-registered verdict: G_focal vs B_cldice ===
    (6 seeds present of 6)

  [PASS] 1. 最暗一層的 Dice 贏 B_cldice
         +0.0184  t=10.93  per seed: +0.0043 +0.0070 +0.0297 +0.0246 +0.0222 +0.0225
  [PASS] 2. 沒有賠掉最亮一層
         -0.0015  t=-4.94   per seed: +0.0008 -0.0014 -0.0027 -0.0020 -0.0021 -0.0016
  [FAIL] 3. 最暗一層的真切斷數比較少
         +1.8500  t=4.50    per seed: +2.40 -0.25 +0.80 +0.45 +2.10 +5.60
```

**判準 1 與 2 過，判準 3 不過。這正是第 2 節事先寫下的三種結局之一，**
**而且是把話講得最清楚的那一種。**

## 5. 判準 1：不只撐住了，還變大了

E7 的三顆種子是 +0.0043 / +0.0070 / **+0.0297**——一顆是另一顆的七倍，
第 0 節說「用現有資料沒辦法分辨這是 E2 那種還是 E5 那種」。

新的三顆是 **+0.0246 / +0.0222 / +0.0225**，彼此差不到 0.003。

合併之後平均從 +0.0136 升到 **+0.0184**，t 從 5.59 升到 10.93，六顆全正。
**離散是舊種子造成的，不是效應本身不穩。**
如果 E7 當初抽到的是後面那三顆，第 0 節整段疑慮不會存在。

這也是這道閘第一次判「通過」。E7 三條中兩條不成立，
E14 的判準 1 不成立——閘會擋，而這次它讓路了。

## 6. 判準 3：不是沒改善，是往反方向

事前寫的是「真切斷數比較少」。實際結果是 **多了 1.85 個**（t=4.50），
六顆種子有五顆是正的。

E7 用同一個指標讀出來的是「沒有變少」。六顆種子讀出來的是**變多**。
`G_focal` 用來換取暗處覆蓋率的東西之一，就是連通性。

配上 [[e15_expected_run_length]]：ERL 說 `G_focal` 比基線多 +573.9 px 的可追蹤長度。
兩件事同時為真，因為 ERL 對「覆蓋更多」和「切得更少」都有反應，
而 `severs` 只對後者有反應。**它多蓋到的比它切斷的多**，淨值是正的，
但代價是實在的，而且只有分開量才看得見。

**所以 `G_focal` 的正確描述是：一個中心線召回率的方法，帶有連通性的代價。**
不是拓樸方法。第 2 節事先就寫好了這句話該怎麼講，這裡只是照著填數字。

## 7. 這份報告差一點是錯的

判準跑出來的第一版說「3 seeds present of 6」，然後印出一份格式完整的判定。
`stratify.py` 和 `break_lengths.py` 各自把種子範圍**手寫成 `(0, 1, 2)`**，
所以它們算的是 E7 的舊種子——**這個「確認實驗」確認的是它自己。**

沒有任何一步報錯。而且那份錯誤的判定檔**開啟了 [[e14_augmentation]] 的佇列閘**，
E14 是在一個假的前提下開跑的（幸好 E14 只用種子 0–2，結論不受影響）。

同樣的手寫範圍在 repo 裡有五份拷貝。已改成 `train.trained_runs()`——掃磁碟，
不宣告範圍——檢查在 `exp/test_trained_runs.py`。
還有第六份：`summarize_gated.SEEDS` 讓判準 1、2 的**種子閘只看三顆**，
配對 t 卻已經吃了六顆，於是「六顆種子」的門檻其實只擋了三顆。
上表是修好之後重算的。

教訓寫進 [[README]] 第六條：
**閘門要擋在「數字是對的」上，不是擋在「檔案存在」上。**
