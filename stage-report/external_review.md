## 實作細節

### A1 ERL 的分岔點怎麼處理 ⭐

**我們用的就是他們打算用的定義**，而且是無意間的 —— 報告沒寫，所以他們會問。

`exp/erl.py:54` 的 `fragments()`：對預測圖做 8-連通標記得到 `pieces`，
取 `covered = skel_gt & (pieces > 0)`，再對 `covered` 做 8-連通標記。
片段就是**被覆蓋的真值骨架的連通元件**。沒有「走」，所以「走到分岔就停 /
隨機選一支 / 先拆成無分岔 segment」這三個選擇一個都不需要做。

為什麼一次標記就夠：`pieces` 是 8-連通的，所以兩個 8-相鄰的預測像素**必然**
在同一個元件裡；用同樣的連通性標記被覆蓋的骨架，就不可能把屬於不同預測元件的
兩段併成一段。這個論證寫在函式的 docstring 裡。

**差異**：他們說「刪掉兩端預測標籤不同的邊」。我們是刪掉未被覆蓋的**節點**。
在 8-連通下兩者等價，因為一條邊的兩端若落在不同預測元件，那兩個像素就不可能
8-相鄰。

### A2 fragment 的長度怎麼算 —— **他們是對的，我們錯了** ⭐

`erl.py` 用 `np.bincount`，也就是**像素個數**。對角步被算成 1，真實長度是 √2。

已修：`exp/erl_length.py`，三種約定並列。

| 測試案例 | pixels | edges | diameter |
|---|---|---|---|
| 水平直線 80 px | 80.0 | 79.0 | 79.0 |
| **45° 直線 40 px** | **40.0** | **55.15** | 55.15 |
| L 形轉角 | 3 | 2.0 | 2.0 |
| T 形分岔（21 px 幹 + 10 px 枝） | 31 | 30.0 | 20.0 |

**45° 的血管被低估 37.9%。**

實作細節，第一版寫錯過一次：對角邊的抑制條件是「**任一**轉角像素存在」，
不是「兩個都存在」。L 形只有一個轉角，但那已經構成兩步正交路徑，
不抑制就會得到 2 + √2 = 3.414。

`diameter` 依他們的建議當敏感度分析並列。分岔上兩者差異最大：
`edges` 把三個分支全加，`diameter` 只留一條路徑。

**哪個對**：ERL 問「追蹤者能走多遠」，而追蹤者在分岔只走一支 —— 那支持 `diameter`。
但 Allen 的參考實作是沿走訪累加邊長（`graph_classes.py:430`），那是 `edges`。
所以 `edges` 是對齊領域的約定，`diameter` 並列報告。

**這不推翻任何比較。** 每一個比較都是兩個臂用同一把尺量的，
單調的單位變換不可能翻轉配對符號檢定。變的是**絕對的可追蹤比例**，
也就是拿去跟別人論文比的那個數字。

### A3 「只有 7% 真的切斷」的判準 ⭐

`exp/break_lengths.py:60` 的 `classify()`：

- 斷口在**真值骨架**上找：`missed = skel_gt & ~pred`，取 8-連通元件。
- 「兩側是不是同一塊」查的是**預測圖**的連通性：把該段膨脹一個像素，
  數它碰到幾個相異的**預測**元件。
  - ≥ 2 個 → `severs`（真切斷）
  - 恰好 1 個 → `intact`（連通性沒斷）
  - 0 個 → `absent`（附近什麼都沒預測）

這是定義而不是代理量，而且有前科：舊版用「該段離最近預測前景多遠」當代理，
它跟 β₀ 誤差的相關只有 0.09，換成上面這個分類是 0.46。代理量在量別的東西。

**注意數字**：報告裡的 7% 是舊的。目前 `K_focal_aug` 的分解是
覆蓋 85.7%、`severs` 2.3%、`intact` 12.0%、`absent` 0.0%。
所以真切斷佔所有未覆蓋中線的 2.3 / 14.3 = **16%**，不是 7%。

### A4 G_focal 的信心閘公式

```
w = 1 + gamma * (1 - 2*|p - 0.5|),   gamma = 1.0,   p = prob.detach()
```

`exp/train.py:567`。權重範圍 [1, 2]，最多加倍。

**逐像素乘進 soft-clDice 內部**，不是乘在整個 clDice 項上。
`weighted_cl_dice()`（`train.py:497`）把權重乘進 precision 和 sensitivity
兩個比值的**每一個 summand**：

```
precision   = (Σ w·skel_pred·target + 1) / (Σ w·skel_pred + 1)
sensitivity = (Σ w·skel_true·prob   + 1) / (Σ w·skel_true + 1)
```

`w = 1.0` 精確還原 CVPR 2021 的損失。

**detach 是刻意的**：不 detach 的話模型可以靠「變得有信心」而不是「變得正確」
來降低損失，那是另一個實驗。

**失敗的變體**（這是他們說比程式碼有用的部分）：
`F_gated` 用影像端的局部對比當權重，**權重範圍完全相同**、其餘完全相同。
它輸給 `G_focal` 0.0177。我們事前預測影像端會贏（因為 E1' 量到模型信心
在最暗那層對人類分歧的 AUROC 只有 0.373），**預測錯了**。

### A5 基線 A_dice 的損失

**BCE + soft Dice**，兩項係數都是 1.0（`compute_loss`，`train.py`）。
不是純 Dice。所以跟他們的基線可比。

## 實驗設計

### A6 為什麼沒做後處理 ⭐ —— **前提不成立，我們有做**

`exp/sweep_score.py:66`，每一次計分之前都先跑
`speckle.drop_small(pred, component_px)`，
`component_px = round(2.08 × width²)`，在 DRIVE 上是 17 px。

**閾值是資料集相對的，不是絕對像素** —— 表示成中位血管寬度平方的倍數
（`hole_sweep.E4_COMPONENT_MULTIPLE = 2.08`），所以同一個常數在 2.83 px 和
5.66 px 的血管上是同一個操作。這是我們的可移植性主張。

不過他們的**方法論主張我們接受**：我們從來沒有把「不做後處理」那一欄
並列在主表裡。要補。

### A7 分層的四層怎麼切 ⭐ —— **沒有循環論證**

- **局部對比**：黑色 top-hat，`grey_closing(image, size=15) - image`
  （`exp/breaks.py:44`）。窗口 15 px，必須大於最寬的血管才能把它閉合掉。
  **只吃原圖，完全不碰模型輸出。**
- **每個像素的分層**：繼承**最近的真值血管像素**的對比四分位
  （`stratify.py:44` 的 `band_map`），所以四個區域鋪滿整張圖。
- **四分位邊界**：從**整個驗證集**的真值血管像素一起算
  （`stratify.py:112`），不是單張影像內切。
  這樣每個模型、每張影像都用同一組邊界。

跟他們的做法一致（原圖 + 標註，不碰模型輸出）。差別只在他們用四分位切在哪個範圍。

### A8 pseudo-replication 之後具體怎麼防 ⭐

四層，都是程式而不是規範文件：

1. **判讀腳本先寫、先自測、再訓練。** 每一個判讀腳本的 docstring 第一行是
   `WRITTEN AND SELFTESTED <date>, BEFORE <什麼> 開始跑`，並且寫下
   **事前預測**。例：`exp/summarize_reach.py`、`exp/select_heldout.py`、
   `exp/matched_cost.py`。
2. **`--selftest` 斷言機制而不是斷言結果。** 用合成資料建構出
   「機制若壞掉就會通過」的情境。例：`select_heldout.py` 的閘門測試餵進
   一個平均 +190、t = 9.4 但符號 2 正 1 負的效果，斷言它**必須不通過** ——
   如果哪天有人把符號規則拿掉，這個測試會爆。
3. **佇列在排程前跑所有自測，失敗就拒絕排。**
   `run_heldout.sh` 開頭跑四個自測，任一失敗 `exit 1`。
4. **run 名單從 CSV 讀，不手寫種子範圍。** E12 的教訓：訓練了種子 3–5、
   兩個腳本計分種子 0–2，判讀檔看起來是完整的。
   現在 `gpu_queue.contaminated_runs()` 直接讀 `erl_best.csv`。

**閘門本身**：配對 t 於 (image, seed) 且 t > 2、**每一顆種子符號一致**、
至少三顆種子。三條全過才叫成立。

## A6 引出的更大問題：跨臂比較沒有匹配成本

他們問後處理，是因為後處理會改變前景量而讓比較失真。同樣的道理，
我們自己的表上：

```
A_dice        Dice 0.8154   traced 30.6%
H_aug         Dice 0.8214   traced 33.7%
K_focal_aug   Dice 0.7993   traced 44.1%
```

`K_focal_aug` 在**明顯不同的前景量**上被拿來跟 `A_dice` 比。
這正是 C1.0 已經付過一次代價的錯誤。

已修：`exp/matched_cost.py`。每個 run 保留十個 epoch，Dice 在其中變動，
所以可以問「這個臂在 **dev** Dice 達到 d 的那個 epoch，**test** 上追多遠」。
掃 d 就得到每個臂的曲線，在共同的 d 上讀。**用 dev 決定 epoch**，
用 test Dice 匹配會把剛修掉的洩漏從後門放回來。
