## 0. 預算：這條線在搶多少分

今天早上量的，`K_focal_aug` @ rule (iv)，report half：

```
真值中心線的去向（按長度）
  被預測蓋到          85.7%
  intact（繞得過去）  12.0%   ← 預算主體
  severs（真的切斷）   2.3%
  absent（附近沒東西） 0.0%
```

**樹不是沒被看見，是被畫歪了。** 預測貼在真血管旁邊，垂直偏移中位 1.4 px
（血管中位寬 2.83 px），持續長度 p90 = 21 px。

把 oracle 分開填回去：

| 條件 | 追蹤 | Dice | 前景 |
|---|---|---|---|
| raw | 47.4% | 0.8015 | 1.00× |
| 只填 intact | **84.0%** | **0.8213** | 1.03× |
| 只填 severs（C1 的天花板） | 52.4% | 0.8055 | 1.01× |
| 全部填 | 97.8% | 0.8251 | 1.04× |

但 `erl_convention.py` 顯示，`erl.py` 只要中心線有一個像素沒被蓋到就切斷骨架
，**即使預測從旁邊繞過去、兩側是同一個連通元件**。改掉那條規則，raw 就從
47.4% 變 67.3%，一個預測都沒改。

**所以誠實的拆帳：**

```
intact 36.6 點  =  19.9 點（我的切割規則）+ 16.7 點（真的沒蓋到）
severs                                     +  5.1 點
                                          ─────────
方法可以搶的                                 21.8 點
```

C1 的連接器只值 5.1 點，已經退場。D1 打的是 21.8 點。**任何簡報都不要用
36.6。**

## 1. 設計約束：修正必須是各向異性的

| | 追蹤 | Dice |
|---|---|---|
| 各向同性膨脹 1 px | 67.9% | **0.6611** |
| oracle 精準填回中心線 | 84.0% | **0.8213** |

往四面八方修會毀掉 Dice；只往該去的方向修是免費的（Dice 還上升）。
**那個差別就是方向場存在的全部理由。**

另一個已知事實決定了設計重心：昨晚那個 34 參數的頭是**線性探針**，而它的軸
誤差 0.243 已經贏過完全不用訓練的 Hessian 濾波 0.322。**主幹特徵裡本來就有
方向資訊。** 所以要設計的是「方向如何作用於分割」的**回饋路徑**，不是更大的頭。

## 2. 階段一（已排入，`exp/run_d1.sh`，tmux `d1`）：天花板

`exp/anisotropic.py` — 來源驅動的定向膨脹：每個前景像素沿**自己的**切線軸
撐開一個橢圓，沿軸半徑 `along`、跨軸半徑 `across`，16 個方向分箱。

**兩個半徑都掃，而掃描本身就是實驗**：如果 `along` 單獨就吃得下預算，修法
是「把血管沿長度延伸」；如果需要 `across`，代表血管畫錯位置。只能表達其中
一種的設計，等於用假設回答問題。

四個來源，各排除一件事：

| 來源 | 意義 |
|---|---|
| `oracle` | 真值方向場。**整條線的上界**，不管預測器將來多好 |
| `predicted` | 訓練好的 `_dir` 頭。與 oracle 的差 = 損失在**預測器**而非機制 |
| `shuffled` | 隨機逐像素軸場。**定向膨脹會加前景，而加前景本身就抬 ERL** —— 這正是閉運算基線贏過 C1 oracle 的原因。若 shuffled 追平 oracle，這張表在量膨脹不是方向，**所有判準作廢** |
| `isotropic` | 純膨脹。要贏的是它，不是 raw |

**Dice 下限 = 0，是量出來的不是挑的**：oracle 填 intact 讓 Dice 從 0.8015
升到 0.8213，所以把前景放到中心線上是免費的，會付 Dice 的修正是在做別的事。
設定在 selection half 選，report half 報，兩個 ERL 慣例都報。

**事前門檻**（`summarize_direction_ceiling.py`，對照 21.8 點的獎金）：

| oracle − isotropic | 結論 |
|---|---|
| < 3 點 | **機制錯了，D1 線停在這裡** |
| 3–8 點 | 值得讓網路自己學怎麼用（走 D-A），不值得手刻層 |
| > 8 點 | **蓋**（D-B / D-C） |

合成資料上機制已驗證：45 度血管上 6 px 缺口，要追到一樣遠，各向同性得付
2.68× 前景、掉 0.435 Dice。

## 3. 階段二：四個架構，全部由階段一的判準決定順序

每一個都**必須**帶「把方向拿掉」的對照，架構其餘完全相同 —— 否則量到的是
容量或階段數，不是方向。兩邊用同一個 checkpoint 選擇準則（rule iv）。

### D-A · 方向條件化的精修階段
第二個小 U-Net，輸入 `[影像, seg 機率, sin2θ, cos2θ, coherence]` 五通道，
第一階段凍結。
- **對照**：同一個網路，方向三通道換成零。
- +117k 參數（20 張影像上要看對照組會不會一起變好 —— E13b 已量到容量會過擬合）。
- 24 runs（2 arms × 6 seeds × 2），約 4 小時。

### D-B · 網路內的各向異性傳播層
`anisotropic.py` 的可微版本，插在最後一個頭之前，**用網路自己預測的方向場
驅動** —— 方向頭因此變成 load-bearing，不再是死路。
- 可學參數只有傳播長度與混合溫度（約 2 個）。
- **對照**：同一層，方向場 detach 後打亂。
- 階段一若 > 8 點，這個先做，因為它就是那個拿到分數的機制。

### D-C · 方向導引的可變形卷積
解碼器的 3×3 取樣位置由切線場決定，**偏移不學**（新增參數為零）。
- 新穎性最高，20 張影像上風險也最高。
- **對照**：偏移來自打亂的場。

### D-D · 各向異性位移損失
懲罰「垂直於真值切線」的位移重於「沿著切線」的位移。不動架構，可與上面任一
個疊。
- **對照**：同權重的各向同性版本。

## 4. 階段三：轉移驗證（任何宣稱都要過）

STARE / HRF / VessMap 都已在本機。這個系列的規矩是任何宣稱要跨資料集成立，
