## 3. Metric table

| Metric | What it captures | Blind spot | Adoption level |
|---|---|---|---|
| **Dice / IoU** | Pixel-wise volumetric overlap | For thin structures, dominated by background pixels → near-meaningless "accuracy" inflation; a single missed thin branch barely moves Dice even though it's a total connectivity failure; conversely a 1-pixel-wide false vessel scores almost the same as a thick one — size-insensitive in the wrong direction | Still the universal default in papers, but explicitly called out as inadequate in essentially every topology-aware paper found this session [verified via search: multiple 2024-2026 papers] |
| **clDice (centerline Dice)** | Harmonic mean of "topology precision" and "topology sensitivity" computed on morphological skeletons of pred vs. GT | Still favors thicker vessels: a 1–2px centerline offset is negligible for a >4px-diameter vessel but devastating for a <4px one — i.e. it inherits a size-bias, just a different one than Dice's [verified via search: benchmarking-metrics MICCAI paper] | Widely adopted as the field's second metric alongside Dice since 2021; treated as close to a de facto standard for tubular structures, used as both metric AND loss |
| **Betti number error** | |β(pred) − β(GT)| — counts topological features (loops/components) without checking WHERE they are | Two topologically-different images with the same total feature COUNT score as identical — no spatial correspondence check at all | Established but recognized as the weaker of the two Betti-family metrics; largely superseded conceptually (not yet in practice) by Betti matching |
| **Betti matching error** | Refines Betti number error by spatially matching persistence-barcode features via induced matching (persistent homology) between pred and GT before counting mismatches | More expensive to compute; differentiable version exists but 3D scaling is nontrivial (dedicated repo exists: nstucki/Betti-Matching-3D) | Newer (2023, ICML), growing adoption in topology-focused papers, not yet mainstream in applied/clinical papers |
| **ARI (Adjusted Rand Index)** | Chance-corrected pairwise clustering agreement between predicted and GT instance segmentations | Not designed for binary tubular masks — this is an instance/clustering metric, native to connectomics (EM neuron segmentation), awkward fit for vessel-mask-only tasks | Standard in connectomics benchmarks (e.g. SNEMI3D-style), essentially unused in vessel/fundus papers [verified via search] |
| **VOI (Variation of Information)** | Sum of conditional entropies between pred/GT clusterings — another connectomics-native instance metric | Same domain mismatch as ARI: assumes instance labels, not naturally defined for a single connected vessel tree | Same as ARI — connectomics-standard, not vessel-standard |
| **Skeleton Recall (loss/metric)** | CPU-cheap connectivity-preserving alternative to GPU-heavy topology losses; recall of GT skeleton points captured by prediction | Recall-only by construction — says nothing about false-positive/spurious-branch precision on its own (needs pairing with a precision-side metric) | New (2024, ECCV/MICCAI), positioned explicitly as a lighter-weight competitor to clDice-family losses; adoption still early [verified via search: MIC-DKFZ/Skeleton-Recall] |
| **Hausdorff distance / 95HD** | Worst-case (or 95th-percentile) boundary distance between pred and GT surfaces | Extremely sensitive to a single outlier pixel/voxel (raw Hausdorff); 95HD softens this but still boundary-distance-only, blind to whether the TOPOLOGY (connectivity, branch count) is right — two masks can have small 95HD and totally different topology | Standard secondary metric across nearly all medical segmentation (not vessel-specific), universally reported alongside Dice in challenge leaderboards |
| **ccDice (connected-component Dice)** | Generalizes Dice to act at the connected-component scale rather than the pixel scale | Very new (2024) — behavior on datasets with many small disconnected true components (e.g. capillary beds) not yet well characterized | Brand new (MICCAI 2024 workshop paper), essentially unadopted outside its origin paper as of this search |
| **Connectivity/breakage-count metrics (tree-length-detected-rate, branch-detected-rate, path-based/junction metrics)** | Directly counts missed branches, false connections, breakages in a tree/graph sense — closest thing to "does the topology make clinical sense" | Ad hoc per-challenge definitions — ATM'22's tree-length-detected-rate is not the same formula as another challenge's junction-metric, so these are NOT cross-paper comparable the way Dice nominally is | Used as the deciding metric in specific challenges (ATM'22) but not standardized as a named, reusable metric the way clDice is — every challenge reinvents its own version |
| **Metrics Reloaded framework** (metrics-reloaded.dkfz.de) | Not a metric itself — a DKFZ-led effort to catalogue/standardize metric choice per task type (incl. clDice's own entry) | Meta-level: doesn't fix the underlying comparability problem, just documents it | Emerging as a reference/citation point across topology papers found this session; not yet a binding standard |

## 4. Measurement culture — blunt statement

**Papers in this area are not comparable by default, and the field mostly knows it and reports around it rather than fixing it.** Concretely, from what surfaced this session:

- A dedicated 2022 paper ("A new baseline for retinal vessel segmentation…", Scientific Data-adjacent, ScienceDirect) exists specifically because **100+ published papers on DRIVE/STARE/CHASE_DB1 had methodological inconsistencies** — wrong FOV handling, inconsistent train/test splits, miscomputed metrics — meaning headline numbers across papers are frequently not measuring the same thing even on the *same* nominal dataset [verified via search].
- STARE has **no official train/test split** at all — every paper invents its own cross-validation scheme, so STARE numbers across papers are close to non-comparable by construction.
- DRIVE does have an official split (train/test), which is why it's treated as the one dataset where cross-paper Dice comparison is semi-meaningful — but even there, papers mixing "accuracy" (inflated by background pixels) with Dice/F1 muddies leaderboards for anyone not reading carefully.
- Topology-specific metrics (Betti-family, ccDice, skeleton recall) are each **less than 3 years old** and none has become a required leaderboard column the way Dice+95HD has for volumetric segmentation — meaning a paper published in 2024 using Betti matching error has no earlier baseline paper to compare against on the same number.
- Challenge-specific connectivity metrics (ATM'22's tree-length-detected-rate) are **defined per-challenge**, not as a portable named metric — so "our tree-length-detected-rate is 92%" from ATM'22 tells you nothing comparable about a different airway paper using a differently-defined breakage count.
- **Net effect:** within one official challenge (same organizers, same hidden test set, same metric code) numbers ARE comparable — TopCoW, ATM'22, ASOCA, ImageCAS-with-official-split are the trustworthy comparison points. Across independently-run papers using the same *dataset name* but their own train/test split and their own metric implementation (DRIVE-the-name, STARE-the-name), comparability ranges from shaky to fictional.

## 5. If you had to pick 2 datasets to start on tomorrow

**1. DRIVE (fundus, retinal vessels).** Reasons tied to access and headroom: zero-friction access (open registration, no gating, instant download), an *official* train/test split so numbers are at least internally comparable, decades of prior work to sanity-check a new pipeline against, and — contrary to the "everything is saturated" fear — the Dice/F1 ceiling sits around 0.82–0.84, not 0.98, so there is real, measurable headroom if the angle is topology-correctness rather than raw overlap. It is the lowest-friction way to get a working pipeline end-to-end before touching anything gated or 3D.

**2. ImageCAS (coronary CTA) or TopCoW (cerebral CTA/MRA) — pick based on 2D-vs-3D appetite.** ImageCAS: open access, an official split (rare in this space), ~1000-volume scale that actually supports a statistically meaningful ablation, and Dice still sitting in the 0.80–0.85 range (headroom intact) — good if the plan can absorb 3D CT compute. TopCoW: MICCAI-official challenge infrastructure (hidden test set = credible external validation), but flag that its plain segmentation Dice is already >90% (near-saturated) — the real headroom there is on the newer graph/topology-classification task (balanced accuracy ~70%), which is a more specific bet.

Both picks deliberately avoid: OCTA-500 (gated behind an email-request password — friction without proportional benefit for a first pass), STARE (no official split — comparability is broken from the start), and the neuron/corneal-nerve sets (interesting but far smaller communities, harder to benchmark against, no clear "official" comparison point).
